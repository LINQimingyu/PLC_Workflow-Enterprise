# AgentsPLC 工厂电气工程企业平台

依据已确认的《LangGraph 修订版》建立的独立企业版实现。首期面向单厂 PLC 团队的 Q／GX Works2 离线工程交付；版本状态为 **企业内核验收候选，未完成真实工厂验收**。

本目录与旁边的 v2.0、v3.0 独立。没有导入旧工作区、案例、凭据、合成日志或人工接受状态。沿用固定 gxworks-agent 工程底座，保留原作者许可与署名。

## 打开与首次登录

本机地址：[http://127.0.0.1:8774](http://127.0.0.1:8774)。

双击 **打开企业工作台.cmd**。首次打开会带入本机设置凭证，要求本人创建管理员的用户名、实名显示名称和密码；没有预设用户名或通用密码。设置链接保存在 **workspace/.local/first-login-url.txt**，仅在本机使用，不要分享。首个管理员创建后，用自己设置的账号登录。

先在“岗位与设置”创建工程师和独立审核账号，为项目分配岗位，再导入原件、填写工具链与需求、审批输入锁。生产知识需要作者之外的两名不同实名审核人。界面中输入的姓名不能替代已登录身份。

Windows 后台启动：powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\启动企业工作台.ps1" -NoBrowser。首次安装运行“安装与构建.ps1”；依赖和本地 PostgreSQL 均放本目录，不安装全局 Skill 或 Windows 服务。

## 平台说明入口

登录后点击右上角“平台说明”，查看分层架构、按编号排列的工程交付工作流及详细说明。工作台、登录页和说明页共用“字体”控制：A−、A＋、当前比例和默认，范围 90%～160%，在本浏览器保留并跨页面同步。

说明页使用可重排的 HTML，字体放大时文字自动换行，不再把整张图压小。项目示例在项目工作台管理，说明页不包含案例标签或案例下载接口。通用说明可独立打开、打印或另存为 PDF；重新生成运行 .venv/Scripts/python.exe deploy/build_platform_guide.py，不读取业务工作区。

未选择项目时，每页只保留项目选择入口与可展开的操作说明；选择项目后进入该页实际操作区。

## Agent、Skill 与工具维护

系统管理员点击左侧“Agent 与 Skill”，可新增与编辑草稿、派生版本、发布、启停和维护模块绑定。该入口不依赖项目。已发布版本不可原地改写；新任务固定所选配置快照，旧合同保留。配置发布与项目授权、工程审批分别管理。

工具配置只能映射已准入实现，新适配器仍需代码集成和独立验证。模型连接继续在“岗位与设置”维护，维护页提供快捷入口。详见 [Agent与Skill维护](docs/Agent与Skill维护.md)。

## 已实现的主要变化

- 五类业务模块：PLC／HMI、故障诊断、电气设计、工艺与产能改善、能耗与运行优化。
- 项目总控可选人工或 Agent；共用工程审查、真实工具验证、文档交付与知识治理。
- FDC 放在工艺与产能改善。新的业务目录没有独立 CIM 模块。
- PostgreSQL 保存实名会话、项目权限、合同、授权、版本、门禁、风险与发布记录。工程文件存为带摘要的版本制品。
- 一套 LangGraph 主图及模块子图，使用 PostgreSQL 检查点；人工决定先落业务记录，再恢复执行。
- 独立审核、每轮补丁人工确认、三轮程序修复失败停止、风险阻断、摘要核验导出。
- 个人参考与生产知识双层治理，独立回归证据、双人批准、撤回与影响定位。
- 电气负载电流、离线能耗、诊断缺项、PLC CSV 和 TT 分析工具；未知参数返回缺项。
- 厂内任务包、限定 MCP 与可选厂内模型 API；模型连接须单独配置、通过合成探针后再授权任务。

## 实际运行边界

本机没有检测到 GX Works2 或其原生工作区适配器。软件已实现受控编译任务队列与独立 Windows 执行器，当前不能在本机证明真实编译通过。仿真首期接收厂商环境产生的原始日志，经独立实名审核人核验；自动仿真适配器尚未准入。

未配置真实模型 Key，模型工具循环仅完成注入合成传输的控制流程测试。未执行真实模型业务调用、现场实施、现场接受或改善效果观察。所有自动验收数据都在 .qa 和独立 QA 数据库。

Docker 文件已提供；当前机器没有 Docker，尚未构建或运行验证。Windows 本地运行路径已验证。原生 CAD、实时数据采集、新厂商与跨厂扩展按后续阶段分别验收。

## 检查

在 app 下运行 ../.venv/Scripts/python.exe -m pytest evals -q。在 app/web 下运行 npm test、npm run build、node tests/enterprise.e2e.mjs。企业测试需要先运行 .venv/Scripts/python.exe deploy/local_postgres.py --qa；测试配置只接受 .qa/config.json 和专用 QA 库。

企业测试不会把合成数据写入生产工作区。源码发布脚本 deploy/source_release.py 使用白名单，排除工作区、数据库、依赖、模型、备份、凭据和 QA 文件。
