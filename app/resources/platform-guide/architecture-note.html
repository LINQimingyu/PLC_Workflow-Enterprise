AgentsPLC 整体架构总览

先区分五件事

对象负责什么不承担什么
工厂岗位对现实工作、授权和确认负责不等于 Agent 名称
工作模块定义目标、输入、交付、审核与交接不按工具或 Skill 数量拆任务
Agent在模块合同与授权范围内辅助处理不能自行授权、批准自身产物或发布
Skill提供方法、依据、判断与停止条件不是执行进程，也不是审批人
工具／适配器完成解析、计算、检索与厂商操作不决定业务是否可以放行

总控可选人工或 Agent。业务控制服务掌握权限、状态迁移与门禁；LangGraph 管理执行位置和工具循环。

从入口到底座

1. 实名人员进入企业工作台，选择项目并按岗位操作。

2. HTTP 服务检查 Host、Origin、会话和 CSRF，再进入业务控制服务。

3. 业务服务核对项目隔离、人员权限、合同、授权、版本、撤回、风险与批准。

4. LangGraph 主图选择已授权模块；模块子图处理执行、工具循环、人工等待与恢复。

5. Agent 按合同加载适用 Skill；确定性工具由受控入口执行，不让方法文件自行运行。

6. 厂商工具任务由独立执行器处理；原生工程、CPU 和验证能力沿用上游工程底座。

7. PostgreSQL 保存业务记录、会话、审计与检查点；文件保存为带摘要的版本制品。

首期采用离线资料。任务包和 MCP 保留同一授权边界，资料不能修改合同或扩大权限。

业务模块与共用保障

层级内容
总控项目受理、工具链与需求基线、计划、授权、进度及交接
五类业务PLC／HMI；故障诊断与维护；电气设计与改造；工艺与产能改善；能耗与运行优化
共用保障工程审查与风险管理；真实工具验证；文档与工程交付；知识治理

FDC 属于工艺与产能改善。平台不设置独立 CIM 业务模块。

六道门禁

门禁核对对象
输入锁设备、CPU、固件、IDE、库、原件、权限和需求
方案锁工程方案、关键 I/O、联锁、验证和回退
工程锁精确候选、原始日志、必要验证及模块交付
风险锁严重／高风险关闭，其他风险有合规处置依据
发布锁终审对象与实际发布包摘要一致
知识锁生产知识完成审核、验证和发布

批准绑定对象版本与摘要。工程、权限、工具链或正式知识依据变化后，重新确定验证与审批范围。

数据与知识

个人参考须本人接受，并保留验证深度和适用性。生产知识需脱敏、领域审核、样板回归及两名不同实名审核人批准。新项目输入资料不必先成为生产知识。

文件原件、候选、工具日志和发布清单分别保留。静态、编译、仿真、现场和效果分别记录，不能互相替代。

当前实现与运行条件

内容状态
LangGraph、PostgreSQL、模块合同、实名权限、门禁、补丁、发布和知识治理已实现企业验收候选
原生 GX 编译入口已实现独立任务边界，真实环境仍待验收
自动仿真适配器尚未准入；可导入真实日志经独立核验
真实模型业务调用、现场与效果不能由软件测试代替
实时设备连接与控制首期不接入

本地实现依据

  • app/src/factory_enterprise/catalog.py：模块与标准制品。
  • app/src/factory_enterprise/service.py：合同、授权、门禁、补丁、风险、发布和知识。
  • app/src/factory_enterprise/graph.py：项目主图、模块子图、人工中断和检查点。
  • app/src/factory_enterprise/operations.py：受控工具、模型调用与副作用凭据。
  • app/src/factory_enterprise/vendor.py：独立厂商工具任务。
  • app/src/factory_enterprise/auth.py、db.py、http.py：身份、存储与传输。
