工程交付工作流

一条主线

需求与基线 → 输入锁 → 方案与方案锁 → 模块候选 → 静态检查 → 真实编译 → 仿真 → 工程／风险／发布终审 → 锁定工程包 → 人工实施与现场接受。

知识治理是独立支线；生产知识另过知识锁。发布、实施、现场和效果是不同状态。

每一站谁接手、交什么、什么时候继续

阶段现实负责人人工或 Agent 做什么交付与继续条件
受理与澄清项目负责人、需求方确认目标、范围、排除项及验收，列出未知信息需求规格与缺项；缺项不自行补成事实
基线工程师收集原件，核对设备、CPU、固件、IDE 和库，分配项目岗位工具链与来源摘要；实名批准输入锁
方案模块负责人比较候选方法，明确 I/O、影响、测试、风险及回退工程方案；实名批准方案锁
模块合同项目负责人确定执行者、独立审核人、必要输入、Skill、工具和预算负责人授权后执行，不原地改写历史合同
候选执行工程师或授权 Agent生成合同内交付，保留差异、文件及测试设计独立审核；缺项返回，候选不代表已实施
静态工程师／审查人对照需求与原件检查范围、类型、连接、逻辑及依赖静态证据，不冒充编译或运行
编译验证工程师、独立执行器在确认的工具链中处理精确候选，保存原始日志当前版本真实编译证据
仿真验证工程师覆盖正常、异常、恢复及约定边界，独立核验导入日志仿真报告，不替代现场接受
风险与终审独立审核人、负责人关闭严重／高风险，确认其他处置和终审版本工程锁、风险锁、发布锁有效
锁包交付负责人绑定需求、方案、工具链、文件、日志、风险和批准导出时再次核摘要；变化后重审
实施与接受现场有权人员在批准窗口人工实施、验证回退与现场表现实施、现场接受、效果分别记录
知识治理知识管理员、审核人提取候选、注明适用性；按知识域接受或审核发布个人参考与生产规范分开

只有需要独立交付和独立审核时才拆任务。业务模块可以由人工完成，不强制为了展示 Agent 而增设任务。

LangGraph 怎么接入这条业务流程

业务决定先保存，再点击“推进／恢复流程”。主图检查有效发布和已授权模块；模块子图根据执行方式处理模型／工具循环或人工提交，并在需要独立审核时等待。

业务工作流中的“编译”“方案锁”等不一定各对应一个图节点。门禁由业务服务判定；图检查点只是保存执行位置，不是批准书。

编译失败以后

每轮修复为：失败证据 → 补丁建议 → 独立人工确认摘要 → 隔离副本应用 → 新版本重编译。

初次编译失败不算已完成一轮修复。连续三轮程序修复重编译失败后停止并记录人工接管。工具环境故障单独计数。

其他停止与返工

情况正确处理
资料缺失或定义不清返回缺项，补齐后重新确认，不生成虚构地址或阈值
权限撤回／版本变化停止后续执行，迟到结果只保留审计；重新确定授权与验证范围
模型或工程操作结果不明记录 unknown 并人工核查，不自动重复
严重／高风险未关闭不发布
实际文件与批准摘要不同拒绝导出，重新审核
正式知识撤回或适用性不符停止引用，并定位受影响项目
缺真实工具能力维持未验证；可以交付有局限说明的分析，不能标为工程验证成功

工作台入口

项目总控：受理、门禁、进度和图恢复。工作模块：合同、授权、候选与审核。工程制品：原件及版本。工具与修复：日志、厂商任务与补丁。工程审查：风险。工程交付：锁定包与交接。知识治理：参考与生产知识。

未选择项目时各页展示说明和选择入口；项目操作需明确选择项目。账号与模型等全局设置可独立进行。
