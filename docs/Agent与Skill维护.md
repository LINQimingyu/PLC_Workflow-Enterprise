# Agent、Skill 与工具维护

## 入口与分工

登录企业工作台，系统管理员选择左侧“Agent 与 Skill”。不必先选择项目。普通账号可看到维护职责提示，不能读取或修改全局配置。

- Agent：模块内的可选执行配置，维护职责与指令，不能取代现实岗位的责任和确认权。
- Skill：维护工作方法、判断依据与停止条件。
- 工具：维护名称、说明及已准入实现的映射，不能通过说明文字安装程序或增加执行权限。
- 模块绑定：为模块明确默认 Agent、Skill 和可选工具的精确版本。

内置模块 Agent 为可选配置基线，不表示必须创建固定数量的 Agent。原有上游专业角色仍由任务上下文路由，candidate 工艺方法不能作为确认规范。项目 Skill 不安装到用户全局 Skill。

## 维护流程

1. 在 Agent、Skill 或工具页筛选模块、搜索标识并查看内容及版本历史。
2. 新增时填写唯一标识、名称、适用模块、内容与维护原因；保存为草稿。
3. 草稿可以编辑，提交时校验所读摘要，避免覆盖其他人的修改。
4. 发布时填写依据并确认精确版本。发布配置不代表已完成生产知识审核或真实工程验证。
5. 已发布版本需通过“编辑为新版本”继续修订；旧内容和任务合同不改写。
6. 在“模块绑定”选择已发布、启用且适用的 Agent、Skill 与工具版本。填写依据后保存。
7. 启停须填写依据。停用不删除版本；再次启用仍需有效的项目合同与执行授权。

工具实现只可选择平台已准入的固定实现，而且必须适用于全部所选模块。新工业协议、MCP 服务器或厂商适配器需另外集成、验证和准入；维护窗口不会运行上传脚本。模型连接仍在“岗位与设置”中维护，任务授权前单独绑定通过探针的厂内模型。

## 对执行与交付的影响

新任务合同固定 Agent 内容、Skill 方法、所选工具版本和摘要。手工任务包、模型请求及发布清单保留这些合同信息。

更新模块默认绑定只影响之后创建的任务；旧合同不会自动升级。停用所依赖的具体版本后，授权、工具或模型执行、成果提交及审核都会重新检查并阻止继续。接受成果依赖的配置失效时，工程门禁也不能误用旧依据。

执行中的请求不能被配置窗口撤销。回写时检查版本状态；失效或停用后的结果只保留为迟到审计，不能直接放行，不能自动重复执行结果不明的请求。

已有合同没有配置引用时，原合同保持不变，内置能力的紧急停用仍会阻止后续执行。启停不修改硬编码的工具白名单、项目授权、预算、实名审核及门禁规则。

## 记录与部署

版本、草稿变更、启停和绑定记录进入 PostgreSQL，使用现有实名会话、Host／Origin 和 CSRF 校验。已发布内容不可变，版本历史与维护原因可追溯。配置变更不写入上游 agent.json 或 SKILL.md，也不覆盖源码内置基线。

配置通过现有数据库备份流程保存，不随源码发布包外发。业务项目、凭据和维护日志不会打入源码包。界面和自动化回归不代表真实模型业务、GX 编译、现场实施或工厂验收。
