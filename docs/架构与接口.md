# 架构与接口

## 模块化单体

企业工作台 → 独立 HTTP 服务 → 企业业务控制服务 → LangGraph 项目主图与模块子图 → 模块 Agent／Skill → 受控工具。

PostgreSQL 保存业务记录、实名会话、项目成员、审计与 LangGraph 检查点；工程字节进入内容寻址制品存储。数据库与制品根目录用 storage binding 配对，不能只替换其中一部分。企业服务没有 SQLite 降级路径。

企业主入口是 factory_enterprise.launch / http.create_app，不挂载旧 cim / factory_v3 的令牌身份接口。旧代码仍用于原生工程底座、解析和回归。源码中保留历史标识，不代表重新引入独立 CIM 业务模块。

## LangGraph 实际执行

主图：inspect → module 子图 或 human_wait → inspect；当前发布包及门禁仍有效才结束。

模块子图：guard → act → tool 循环 → wait_result → review。人工／任务包会在 wait_result 中断；API 可运行受预算限制的模型和工具循环；候选在 review 中断。所有恢复只携带“重新检查业务记录”，不接受客户端把 approved=true 注入检查点。

PostgresSaver 保存主图、嵌套子图和人工中断。项目级 PostgreSQL 会话锁阻止重复并发恢复；副作用另有持久化幂等键与请求摘要。已完成请求返回原凭据，结果不明的请求停止。新建授权不自动重复旧请求。

每次图恢复、模型请求、工具调用、结果写入与审核，重新检查人员、项目、授权期限、撤回、输入版本、合同摘要和知识适用性。角色变化提升授权纪元，使旧授权与批准失效。

业务决定和操作意图先提交，再执行后续图节点。任务记录保存不可原地改写的合同；授权、执行状态、回传、审核和续期各有记录。文件先写入按摘要命名的不可覆盖 blob，再在事务中登记；事务失败遗留的无引用 blob 不会成为工程成果或发布内容。

## 业务记录与失效

ep_users / ep_members / ep_sessions：密码哈希、实名身份、项目岗位、服务端会话与 CSRF。浏览器从会话取得身份，请求体中的 actor 被拒绝。

ep_records：项目、合同运行、授权、制品、日志任务、风险、门禁决定、补丁、工程发布、知识、指标、历史映射和组件准入。

ep_events：只追加审计，含前一记录摘要。应用操作经过事务锁；数据库管理员仍是受信任管理边界，哈希链不代表可以抵抗有超级用户权限的恶意修改。

制品版本有独立 ID、来源、字节摘要、记录摘要和适用工程上下文。active 是单独生命周期标记，历史字节与记录内容保留。工程交付需检查当前基线及模块明确引用的输入。旧验证只能用于绑定的候选与工具链，旧批准不能用于变化后的对象。

发布清单包含精确制品集合、合同、工具链、各阶段原始日志、风险、门禁决定、正式知识版本和摘要。被验证或审查引用的历史制品也进入包。导出重新检查所有文件、权限、门禁和正式依据；知识撤回后不能继续用旧包作为当前有效交付。

## 标准制品

ToolchainProfile、RequirementSpec、EngineeringPlan、CodeBundle、ElectricalDesignPackage、DiagnosisCase、ImprovementPackage、EnergyBaseline、CompileResult、SimulationReport、RiskFinding、ManualInterventionRecord、EngineeringReleaseManifest、KnowledgeVersion，以及 Original、AnalysisDelivery、PatchProposal。

运行时的人工接管记录在 intervention 记录中，补丁在 patch，发布清单在 release，知识版本在 knowledge；不是所有类型都允许直接上传。验证、补丁、发布与接管必须走相应业务接口。

工程交付和分析交付分开。静态、编译、仿真、现场、效果是独立 stage，不能互相替代。Imported 日志是人工报告与独立核验；工具执行则是 origin=tool。QA 记录及其工程清单始终带 environment=qa，生产启动拒绝混用。

## 接口分组

所有业务接口要求当前用户会话。写操作同时要求完全相同的 Origin 和 X-CSRF-Token；Host 必须精确匹配配置。当前仅开放明确本机 HTTP Origin。

| 分组 | 路径与用途 |
|---|---|
| 身份 | /api/setup、/api/session、/api/users |
| 项目 | /api/projects、/{id}/members、/{id}/controller |
| 模块 | /api/projects/{id}/runs；/api/module-runs/{id}/authorize、renew、revoke、submit、review、model、tools、bundle |
| 图 | /api/projects/{id}/graph、graph-reset |
| 制品 | /api/projects/{id}/artifacts；/api/artifacts/{id}/file |
| 验证 | /api/projects/{id}/tool-jobs、vendor-jobs；/api/tool-jobs/{id}/verify、reconcile |
| 补丁 | /api/projects/{id}/patches；/api/patches/{id}/approve、apply；/api/projects/{id}/takeover |
| 门禁／风险 | /api/projects/{id}/gates、risks；/api/risks/{id} |
| 发布 | /api/projects/{id}/releases、lifecycle；/api/releases/{id}/export |
| 知识 | /api/projects/{id}/knowledge、knowledge-search；/api/knowledge/{id} |
| 治理 | /api/projects/{id}/metrics、legacy-mappings、components |
| 模型 | /api/models、/{id}/probe；/api/operations/{id}/reconcile |

项目读取只返回获准项目；系统管理员不会绕过项目成员检查。文件 ID 只映射到服务端受控 blob，不能传路径。工具只允许模块白名单和合同中的输入；没有任意 shell、网络下载、在线设备写入接口。

合同核心字段为 module、goal、scope、inputs、outputs、acceptance、owner、executor、reviewer、skill、tools、budget、knowledge、human_points、stop_conditions。inputs 绑定 ID 与摘要；Skill 保存方法内容与摘要。合同变更须新建运行，旧合同保留。

需要复用上游专业方法时，操作者可显式给出 legacy_context 的 scenario、area、equipment，服务使用基线 CPU 调用 Registry.route，再只把本模块适用的方法快照纳入合同。未给上下文时不推测工段或设备；candidate 工艺方法不构成规范，也不会生成额外任务。

legacy-mappings 只登记历史命名域、原标识、原件 ID 与来源摘要，并标为 requires_revalidation。不能修改旧任务合同或把原型接受状态搬成企业批准。

components 登记开源组件名称、版本、许可证、来源摘要、网络、权限、回归证据及准入决定；没有目录即运行任意插件的入口。

## 模型与 MCP

首期仅允许经过实际部署确认、解析到私有地址的厂内模型。官方云端地址不能标成厂内。业务请求需经过合成探针、绑定模型、负责人授权及预算检查。SDK 和供应商响应解析复用 model_runtime/provider.py，禁用自动重试、环境代理与跳转。默认关闭 LangSmith、Haystack 和 OpenTelemetry 外发跟踪。

Windows Key 进入凭据管理器，目标绑定端点及模型；Docker Key 从端点绑定的只读文件读取。数据库、日志、任务包和源码清单不含明文 Key。单次请求内容及 token 预算均有上限，缺少可信用量时停止后续执行。

factory_enterprise.mcp 提供 stdio 的 module_read_contract、module_read_evidence、module_run_tool、module_submit_candidate。启动指定配置和运行 ID，EP_MODULE_TOKEN 由负责人本次授权返回，通过进程环境传入；不能放命令行或源码。每次调用重新验证 grant。MCP 不提供授权创建、关键门禁、补丁应用、风险豁免或发布能力。

## 工具边界

确定性工具：电气负载电流及选型待核项、单位合格品能耗、诊断上下文缺项、PLC CSV 解析／差异、TT 日志质量与瓶颈分析。

厂商编译由 factory_enterprise.vendor 的独立 Windows worker 执行，复用上游 application.native_validation 与 gxworks2.workspace_adapter。排队前绑定验证模块授权、候选摘要、CPU、方案与覆盖；执行前和回写时再次校验。仿真自动适配器未准入，返回 unavailable，允许导入真实日志经独立核验。

电气计算不自动完成短路配合、降容或正式 CAD；报告明确列出待核项。未知参数、零合格品等返回缺项，不制造选型或改善结论。

参考：[LangGraph 检查点](https://docs.langchain.com/oss/python/langgraph/persistence)、[人工中断](https://docs.langchain.com/oss/python/langgraph/interrupts)。具体运行版本见依赖锁及组件清单。

## 只读平台说明

工作台“平台说明”入口使用 /api/guides/index，沿用实名会话与 Host／Origin 检查。固定 allowlist 只提供整体架构、工作流及两份详细说明。旧案例相关接口返回不存在；实际项目资料归属于项目制品与权限域。

文件必须与本地说明清单的 SHA-256 一致。HTML 仅允许摘要绑定的脚本，通用工作台原有 CSP 不放宽。iframe 保留独立来源沙箱；字号通过限定消息类型和来源窗口同步，高度由正文实际尺寸计算。

说明页以 HTML 分层卡片和编号步骤展示，使用自适应字体及布局；不再压缩整张 SVG。应用及说明页使用同一浏览器阅读比例，允许 90%～160%，不修改模型配置或业务权限。deploy/build_platform_guide.py 从通用源文档和模板重建说明，不读取案例或业务 workspace。

项目受理计划保存在普通版本制品中，展示为“待补资料 · 任务计划尚未授权”。计划卡片不创建执行合同，不产生授权或门禁批准。

前置计划制品使用 IntakePlan（scope、tasks、missing），与执行合同和 AnalysisDelivery 分开。早期无 run_id、序列为 project-intake 的 AnalysisDelivery 仅按历史前置参考处理，保留原记录；它不能满足分析交付门禁。正式模块成果与其他分析交付继续校验工程上下文。

## 全局能力维护

factory_enterprise.maintenance 管理 capability_version、capability_control 和 capability_binding。/api/maintenance 提供管理员目录、版本详情、新建／编辑草稿、发布、启停及模块绑定接口。/api/catalog 面向实名用户返回当前有效的默认版本与工具清单，不外发方法正文。

任务创建时将 Agent、Skill 与工具版本冻结进合同；执行、授权、回写和工程门禁重新检查依赖版本，旧合同不随默认绑定变更。详见 Agent与Skill维护.md。
