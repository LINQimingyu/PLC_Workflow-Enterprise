# 实施与验收

日期：2026-11-04。实施依据为用户确认的《工厂电气工程企业平台优化方案——LangGraph 修订版》。本目录是新的企业内核实现，旁边 v3.0 保留为原型及回归资产。

## 方案对应

| 方案要求 | 本次实现 | 验收边界 |
|---|---|---|
| 按工作模块组织，不固定 Agent 数量 | 五类业务、总控及四类共用保障；任务按独立交付建立 | 不是把旧 34 个角色逐个搬成导航 |
| 人工或 Agent 总控 | 负责人选择；Agent 可提出计划、分派已授权任务、审核明确允许委托的普通关口 | 关键门禁、补丁、风险及发布保留实名人工决定 |
| 一套 LangGraph | 项目主图、嵌套模块子图、模型／工具循环、interrupt、PostgresSaver | 重建实例后可恢复；业务记录始终是权限依据 |
| PostgreSQL 企业数据域 | 实名用户、项目成员、合同、授权、制品、风险、发布、知识、审计 | 无 SQLite 降级，不导入旧接受状态 |
| 权限与版本检查 | 请求身份来自会话；项目权限、授权纪元、摘要、撤回与适用性检查 | 账号由管理员实名录入，未对接企业 SSO |
| 六道门禁 | 输入、方案、工程、风险、发布、知识；绑定当前对象摘要 | 门禁被退回或基础变化后，旧批准不能误用 |
| 候选及原件 | 内容寻址文件、独立版本、来源、不可覆盖字节、依赖与工程上下文 | 原件保留；历史依赖不原地改写 |
| 真实验证分层 | static / compile / simulation / field / benefit 分开；工具任务与模型分离 | 导入日志为人工报告，经另一实名人核验，不标成自动编译 |
| 补丁人工确认与三轮停止 | 失败版本绑定、补丁摘要批准、新副本、重编译、三轮失败接管记录 | 环境故障单独计数；当前机器不能执行真实 GX 验证 |
| 风险与发布 | 严重／高风险不可豁免；独立处置；锁定清单、依赖闭包、导出重验 | 发布、实施、现场、效果分开；缺证据不能填写成功 |
| 个人／生产知识 | 本人接受参考；生产脱敏、领域审核、原始回归证据、两名不同实名审核人、发布／撤回 | 默认按权限与 CPU／设备适用性检索；当前为离线关键词检索 |
| 历史标识与开源准入 | 映射 API 保留 namespace、旧 ID、来源摘要；组件记录版本、许可、网络、权限与回归 | 历史映射标为待复核；组织生产准入仍须工厂完成 |
| 电气与能耗扩展 | 电气负载电流、BOM／连接草稿，单位合格品能耗；诊断缺项、PLC CSV、TT 工具 | 未实现完整保护配合或原生 CAD 自动交付；缺参数返回缺项 |
| 业务基线优先 | 指标保存口径、窗口和来源，无同名基线时不能建目标 | 未预设节约百分比或固定交付周期 |

## 自动验证

最终运行命令和结果保存在本机 .qa/validation-results.json 与相应日志；浏览器报告和截图在 .qa/browser。后端包含继承的 v2／v3 回归及企业边界测试。所有企业测试都使用 PostgreSQL QA 库和 .qa 文件，不读取业务 workspace。

本次结果：后端 200 项通过（其中企业验收 35 项），前端 100 项通过，TypeScript／Vite 构建通过，浏览器 9 组通过且无页面异常，Python 依赖检查通过。数据库恢复演练恢复 21 个早期 QA 项目，清除了会话并撤销授权，没有派发任务。

重点覆盖：检查点重建、重复恢复、并发副作用幂等、撤权与迟到结果、模型工具循环、未知请求停止、预算、独立审核、三轮修复停止、环境故障分开、真实与合成证据隔离、风险禁止自审和高风险豁免、知识双审与撤回、已结束图重新检查有效性、历史日志打包、发布篡改拒绝、Host／Origin／CSRF 及项目隔离。

浏览器走过首次设置、实名登录、岗位分配、原件上传、基线及方案锁、LangGraph 等待、跨用户提交／审核、分析发布与导出，并检查 1440／1024／390／320 宽度。截图是合成 QA 样板，不代表真实工程验收。

已执行 PostgreSQL 一致性备份、摘要校验、新空数据库与新制品目录恢复；恢复移除会话、撤销授权并不派发任务。恢复验证报告在 .qa/backup-restore-report.json。

## 界面修复记录：未选择项目时的导航

修复所有导航在未选择项目时共用同一个首页的问题。现在八个导航分别显示对应内容、前置条件与项目选择入口；创建实名用户、配置厂内模型等全局设置可直接使用，不要求先创建或选定项目。不会自动选择项目或生成示例项目。

新增浏览器回归覆盖无项目的八个导航、未选项目时创建账号，以及清空／重新选择项目后的页面恢复。本次仅修改前端，前端 100 项检查及构建通过；完整浏览器回归更新为 12 组。原后端 200 项为此前完整验收结果，本次未改后端，未重复执行。

- 原生 CAD、新厂商、实时平台／受控采集、多厂、企业身份源和高可用不冒用本次离线单机验收结论。

## 工厂下一阶段验收

选择一套已获授权的真实 Q／GX Works2 工程，先记录人工业务基线和工具链。分别验收真实编译原始日志、一次人工确认补丁闭环、正常／异常／恢复仿真、风险关闭、锁定包与回退。之后再由有权人员安排人工实施、现场接受及效果观察。

真实项目材料由项目准入进入企业域；不要把当前 QA 数据、旧原型合成结果或口头接受迁移为生产证据。生产知识及新增组件需用实际样板回归完成组织准入。
