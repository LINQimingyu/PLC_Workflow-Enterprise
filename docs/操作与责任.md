# 操作与责任

## 五个概念分别负责什么

| 对象 | 回答的问题 | 责任边界 |
|---|---|---|
| 工厂岗位 | 谁承担现实责任和确认权 | 登录用户、项目岗位和独立审核人 |
| 工作模块 | 本次工作交什么，交给谁 | 目标、范围、输入、交付、验收和交接 |
| Agent | 谁在授权范围内辅助处理 | 可以提议、调用允许工具、提交候选；不能自行授权或发布 |
| Skill | 采用什么方法 | 步骤、依据、判断规则和停止条件；不自动制造任务 |
| 工具／适配器 | 哪个确定性能力实际执行 | 解析、计算、检索、厂商操作；不决定审批和业务权限 |

LangGraph 保存执行位置，业务服务决定某项操作是否仍被允许。总控 Agent 不是超级管理员。所有关键工程门禁、补丁确认、风险处置和发布均由有权实名用户完成。

## 岗位与模块

| 工作模块 | 现实责任岗位 | 交付与交接 |
|---|---|---|
| 项目总控与基线 | 项目负责人 | 受理、工具链、需求、范围、计划、授权和交接 |
| PLC／HMI 工程 | PLC／自动化工程师 | 候选程序、I/O、变量、HMI 点表、差异、测试和回退 |
| 故障诊断与维护 | 设备维护工程师 | 假设、证据、反证、排查、维修、复验、实际结局 |
| 电气设计与改造 | 电气工程师 | 参数、计算、BOM、连接关系、图纸草稿、施工影响 |
| 工艺与产能改善 | 工艺／IE 工程师 | FDC、TT/CT、瓶颈、动作、窗口与改善效果 |
| 能耗与运行优化 | 能源／运行工程师 | 计量口径、基线、单位合格品能耗、待机损失和节能候选 |
| 工程审查与风险管理 | 独立工程审核人 | 问题清单、整改、证据、风险关闭或有权豁免 |
| 真实工具验证 | 验证工程师 | 精确版本的原始日志、覆盖、验证结果和局限 |
| 文档与工程交付 | 交付负责人 | 发布清单、锁定包、实施、现场、效果分别交接 |
| 知识治理 | 知识管理员及领域审核人 | 候选、脱敏、回归、双审、发布、撤回和退役 |

不固定 Agent 数量。同一业务模块可由人工、厂内任务包或已批准模型处理。只有需要独立交付和独立审核的工作才建任务。

## 项目岗位权限

owner 管项目计划、成员、授权、关键门禁、发布和接管；engineer 建工程制品、提交候选、提出补丁；reviewer 审核成果、核验他人导入的日志、处置风险与批准生产知识；validator 登记验证和创建厂商任务；knowledge 管知识治理；viewer 只读。

系统管理员创建实名账号，不自动获得其他项目的工程审批权限。项目创建者初始具备本项目全部岗位，可将不同职责分配给不同用户。模块合同强制执行者与审核人为不同账号。补丁、日志核验和风险关闭要求独立人员。生产知识要求作者之外两名不同实名审核人。

实名信息由管理员维护；本地账号认证尚未对接企业 SSO／HR 身份源，不能用它替代企业对人员身份的核验。

## 从空项目到工程包

1. 创建项目，选择五类业务模块中的必要模块、人工／Agent 总控和工程／分析交付类型。
2. 创建人员并分配岗位。随后改变权限会使基线批准和任务授权失效，需要重新核对。
3. 导入 Original 原件，选择资料分级，保留字节与 SHA-256。普通输入用途为 reference；原始测试、编译和现场记录用途为 evidence。每个独立原件使用独立制品序列名，修订同一原件时沿用序列名。
4. 建 ToolchainProfile，填写设备、Q CPU、固件、GX Works2 版本、库版本、原件 ID 和允许操作。再建 RequirementSpec，写清目标、纳入／排除、验收、关键 I/O 和联锁。
5. 审核“输入锁”；缺项不会放行。建立工程方案，写明验证与回退，审核“方案锁”。
6. 按需要建立模块合同：选择精确输入、输出、执行人、独立审核人、Skill、工具与预算。由负责人授权。合同不能原地改写，需变更时撤回后新建。
7. 人工提交、交给厂内 Agent 任务包，或绑定通过探针的厂内 API。返回是候选。程序包必须附实际候选文件，不能只交摘要。用独立审核账号审核。
8. 对当前候选分别登记静态、编译和仿真证据。工程包必须具备各阶段真实证据；分析交付必须明确未完成的验证。导入日志只标记为操作员报告，需另一人核验后才能使用，不会标为自动编译。
9. 编译失败后提补丁，绑定失败日志、基线、完整候选快照和回退。另一人核对摘要确认后，工程师应用到新版本，再编译。原件不覆盖。初次失败不是修复轮次；三次已确认补丁的重编译均失败后停止。环境故障另计。
10. 风险清单中严重／高风险必须关闭。其他风险也需证据和有权独立处置。风险处置关联工程版本，工程或权限变化须重审。
11. 审核工程锁、风险锁、发布锁，再生成锁定包。下载前再次核对摘要及当前权限、批准和知识依据。
12. 工程包发布之后，人工实施、现场接受和效果观察仍分别记录。先保存真实人工基线，再设置改善目标。

“推进／恢复流程”只运行已获授权的工作，并在需要业务决定、候选提交或独立审核时等待。这个按钮不能代替门禁审批。

## 总控 Agent 的权限

总控可提交计划候选，使用 control.dispatch 分派本项目已有授权任务，或使用 control.review 审核负责人明确允许委托的普通模块关口。无法建立新授权、修改合同、跨项目审核、审核自身产物、处理关键工程门禁或风险豁免。任务包和 MCP 同样受业务服务检查。

## 等待、撤回与未知结果

任务授权有效一小时。负责人可填写依据后续期；续期会使旧 Agent token 失效，保留预算和合同。版本或权限变化后不能用续期掩盖变化，应建立新合同。

模型和厂商操作在真正执行前保存意图记录。重启后 running 变为 unknown，不会自动重复。负责人核查后关闭未知记录；需要再次执行时新建并授权任务。核查不会把 unknown 改成验证成功。

撤回任务后，迟到结果只进审计。卡在旧子图时，负责人可用“流程重新立案”记录交接原因，撤回未完成任务并创建新流程实例，旧检查点保留。

## 知识

个人参考须本人接受，并保留验证深度和适用性；默认只向本人提供参考检索。正式工程依据只能选有权限、适用性相符的已发布生产知识。

生产候选需来源、适用性、验证深度和资料分级。脱敏与领域审核保留依据；样板回归必须关联独立原始测试记录。作者之外两名不同实名审核人批准后再发布。发布不能降低来源资料等级，也不代表外发批准。撤回与退役会停止后续使用并返回受影响任务和项目。

项目新输入按项目准入使用，不必先变成生产知识。
